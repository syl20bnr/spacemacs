* Overview

This repository is a personal fork of the official [[https://github.com/syl20bnr/spacemacs][Spacemacs]] distribution.

** Upstream Synchronization Policy
To prevent merge conflicts when pulling or rebasing against upstream Spacemacs:
- The root ~README.md~ and core Spacemacs files must *remain untouched*.
- All custom notes, maintenance procedures, and repository additions should be documented in this file (~README-additional.org~) or under ~.spacemacs.d/~.

* Submodules and Custom Assets

** .spacemacs.d Submodule
All user configuration, personal layers, and automation live in the git submodule:
- Submodule path: ~.spacemacs.d~
- Repository: ~git@github.com:lesliebinbin/.spacemacs.d.git~

*** Configuration Directory Discovery
The fork-specific bootstrap in ~early-init.el~ selects the customization
directory before loading the core:
1. ~SPACEMACSDIR~, when explicitly set.
2. The repository-local ~.spacemacs.d/~ alongside ~early-init.el~, if it exists.
3. ~$XDG_CONFIG_HOME/spacemacs/~, if it exists.
4. =~/.spacemacs.d/=, even if not yet created.

This small bootstrap exception to the core-file policy preserves local
configuration discovery across upstream synchronization.  ~user-lisp-directory~
also follows the selected customization directory.

** Reusable Agent Assets
Reusable agent skills, runbooks, and profiles are located in ~.spacemacs.d/agents/~:
- Runbooks: ~.spacemacs.d/agents/runbooks/~
- Skills: ~.spacemacs.d/agents/skills/~
- Profiles: ~.spacemacs.d/agents/profiles/~

Notable workflows include:
- =emacs-package-fork-patch=: Procedure to fork, test with =eldev=, patch, and wire unmaintained Emacs packages into Spacemacs via Quelpa recipes without relying on fragile runtime monkey-patching.
- =scikit-build-cuda-extension=: Bootstrap CMake/CUDA-backed Python C++ native extensions.

* Cross-Repository Feature Runbooks

Features spanning this repository, the =.spacemacs.d= submodule, and external
component repositories are recorded under =runbook/= in this parent
repository.

- Each feature has one self-contained Org file in its project directory, such
  as =runbook/emacs-jupyter-eval/renderer-001.org=.
- Org TODO keywords record lifecycle state within the feature file.
- Feature files contain context, requirements, decisions, scope, acceptance
  criteria, and outcomes. Reusable agent-routing and delegation policy belongs
  in =AGENTS.md=.
